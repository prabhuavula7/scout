# Roadmap

## Done

- Core pipeline: import (OpenAPI/Swagger URL or raw text), documentation crawling + chunking + embedding, understanding synthesis, grounded chat with citations.
- Local-first architecture: `packages/store`'s `LocalFileStore` persists everything under `~/.scout/runs/`, no database or server required for the default path.
- `scout` CLI: `understand`, `list`, `rm`, `chat`, `export`, `watch`, `research`, `serve`, `connectors`, `config`.
- Local web app (`scout serve`), bound to `127.0.0.1`, no login, reading the same run directories live. Not view-only: a persistent sidebar (Runs / New / Settings) and a "New" tab run the same `understand` pipeline as the CLI (fire-and-poll: the request returns immediately, the run's status page polls live), so a UI-only user never has to touch the terminal after the initial `npm install -g @dotapk7/scoutcli && scout serve`. Deleting a run (`scout rm`, or the trash icon on the Runs page) is available from both surfaces too.
- Connectors as JSON config (`packages/connectors/registry/*.json` + `~/.scout/connectors/` overrides), not code.
- `scout watch`: polls doc URLs, hashes content, re-runs documentation + understanding agents on change, archives the previous snapshot to `history/`.
- `scout research`: related articles/tutorials/use cases via a configured search provider, surfaced in the viewer and `scout export`.
- **Provider-agnostic LLM + search**: `packages/ai` implements OpenAI, Anthropic, Azure OpenAI, OpenRouter, and a generic OpenAI-compatible adapter (covers local/open-source models via Ollama, LM Studio, vLLM, etc); `packages/agents/src/search` implements Tavily and SerpApi. Multiple entries can be configured per role (chat/embedding for LLMs) with priority-ordered automatic fallback. Config is shared between the CLI (`scout config llm`/`scout config search`) and a Settings tab in the web viewer, both reading/writing the same `~/.scout/config.json`; a pre-existing single-key config or `OPENAI_API_KEY`/`TAVILY_API_KEY` env vars migrate/fall back automatically.
- `scout mcp`: MCP server exposing `understand_platform` / `ask_platform` / `list_platforms` for Claude Code, Codex, Gemini CLI, and other MCP-speaking agents.
- Dormant hosted mode (`apps/api` + `apps/workers`, Fastify + Clerk + Postgres/pgvector + BullMQ/Redis) kept working but excluded from the default build/dev/test pipeline, for anyone who wants a multi-user hosted deployment later.
- **npm-publish readiness**: `packages/cli` bundles the connector registry JSON and a prebuilt `apps/web` viewer (`.next` output, minus webpack's build cache and Next's own trace files) inside `dist/`, with `next`/`react`/`react-dom` as real dependencies rather than pnpm workspace links, so `scout serve` runs the same way from a real `npm install -g @dotapk7/scoutcli` as it does in the monorepo. Verified with a real `npm pack` + global install into an isolated prefix, outside the monorepo: `connectors list`, `scout serve`, and the viewer's HTTP response all work. Published to npm as `@dotapk7/scoutcli` (the unscoped `scoutcli` was rejected by npm's name-similarity policy against an existing `scout-cli` package); the `scout` command name is unaffected. Verified again post-publish with a real `npm install -g @dotapk7/scoutcli` from the registry, outside the monorepo.
- **Failure reasons surfaced in the web UI**: a failed run used to show only a red "Failed" badge with no way to see why short of the CLI's stderr or `agent-runs.jsonl`. `GET /api/runs/[slug]` now returns the most recent failure's error message (`lastError`), rendered as a banner on the run's page.
- **Thin/JS-rendered doc page detection**: `packages/agents/src/documentation-agent.ts` flags any crawled page whose extracted markdown comes back under ~500 characters (a heuristic for "this is a JS-rendered SPA shell cheerio's static fetch can't execute," the most common real cause). Surfaced as an amber warning banner on the run's page (`platform.docsCrawlWarning`), not a silent thin answer.
- **Pre-run crawl size estimate**: `scout understand` prints a one-line estimate (seed URL count, known byte/token size, crawl depth/page cap) before starting; the web "New" form has an on-demand "Preview crawl size estimate" button hitting the same `estimateCrawlCost` helper (`packages/agents/src/crawl-estimate.ts`). Deliberately doesn't attempt a $ figure (provider/model pricing isn't tracked and would go stale); states token/byte counts only and defers cost to "depends on your provider's pricing."
- **Recursive documentation crawling**: `runDocumentationAgent` now optionally follows same-origin links found on each crawled page, breadth-first, up to `--docs-depth` hops (default 1) and hard-capped at `--docs-max-pages` (default 20) regardless of depth, so a crawl can't spider an entire site unbounded. `--docs-depth 0` reproduces the old fixed-set-only behavior exactly.
- **Disclosed understanding scope**: endpoint summaries and doc chunks feeding synthesis are capped (300 / 100, up from silent caps of 150 / 40) to bound prompt size/cost; doc-chunk selection now samples evenly across every crawled source page (`getRepresentativeDocChunks`) instead of just the most-recently-crawled pages, and a run's page discloses via an amber banner whenever a cap was actually hit, instead of silently looking complete.
- **Web UI parity with the CLI**: a research trigger on the Understanding page (same pipeline as `scout research`), chat/research error handling that surfaces the real failure reason instead of an unhandled 500, and custom error/404 pages instead of Next.js's defaults.
- **Docker support**: `Dockerfile` + `docker-compose.yml`, `docker compose up` to run Scout with no Node/pnpm install at all. Built and run for real during development (not just written): caught and fixed a dangling `.env.local` symlink breaking the build, an `npm install` incompatibility with `workspace:*` devDependencies, and a missing `scout` binary on `PATH` inside the container. Verified end-to-end: real `scout understand` run via `docker exec`, reachable through the mapped port, surviving a container restart via the named volume.
- **Automated web UI test coverage**: 46 tests across API route handlers and interactive components (sidebar, Runs list, New-run form, chat, Understanding page, Settings), closing the gap this list used to flag; `apps/web` now has real automated coverage alongside `packages/store`/`packages/cli`/`packages/connectors`/`packages/agents`.
- **MCP client compatibility verified**: the stdio JSON-RPC protocol handshake (`initialize`/`tools/list`/`tools/call`) tested directly, plus a real Claude Code client connection. Setup snippets for Claude Code, Claude Desktop, Cursor, and Codex CLI added to the README.
- **Fresh screenshots**: the old web-app UI's screenshots (pre-CLI-pivot) removed from `public/`; replaced with 7 new ones captured against the current interface (Runs, New, Understanding with its table of contents, entity diagram, API Explorer, AI Chat, Settings) and embedded in the README.

## Not yet implemented

- **More connectors**: 18 are declared in `packages/connectors/registry/`, only Contentful and Bynder have been run end-to-end. Adding one is now a JSON-only PR; see `CONTRIBUTING.md`. Verifying one requires a human to actually compare the output against the platform's real docs, so this isn't something to batch-automate; left as ongoing/contributor work.
- **More import kinds**: GraphQL introspection, GitHub repo spec discovery, Postman collections, HAR files. `packages/agents/import-agent.ts` only handles OpenAPI/Swagger URL and raw text today.
- **Local vector search upgrade path**: `packages/store`'s hybrid search is brute-force in-memory cosine similarity + keyword blend, fine at CLI/single-platform scale. `sqlite-vec` is a documented drop-in if chunk counts get large.
- **No published Docker image**: `docker compose up` always builds locally (`build: .`); there's no image on Docker Hub/GHCR yet for a pull-and-run without a local build.

## Suggested build order for contributors

1. Run `npm publish` for `packages/cli` (the packaging itself is done and verified; this is the one remaining action, gated on an npm account/org decision).
2. Pick an unimplemented connector from `packages/connectors/registry/`, run `scout understand` against its real spec + docs, and flip `implemented` to `true` once it works cleanly.
3. Add a new import kind to `packages/agents/import-agent.ts` (Postman collections are probably the easiest next one, same endpoint-shape output).
